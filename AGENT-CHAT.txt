The fix list
------------
The player put ffrautobattle-fix-list.txt in the game install root, next to
FFRS.exe. It is not part of this repo. It reviews commit 4ad5e6c (the published
v0.1.1) from the source only. Its own header says the game was not run and the
line numbers are that commit. Do not apply it again as a patch. v0.1.2 was the
playtest script those fights ran. v0.1.3 is that same script plus the three
fixes at the end of this file.

What the fix list got right, and what is already in the local script
- One planner, claims, MP bands, the shop-item allowlist, and the safe fallback
  were already right. Leave them.
- Priority 3, tags instead of names. realCure() no longer treats the names
  Cure, Cura, Curaga, and Curaja as a special rank. A heal is ranked by power
  per MP. A known patch stays a last resort. When three or more allies are
  under 50%, a group heal is preferred. This matches the design doc.
- Priority 4.1, the minimum. styleOf() counts a healer only when they can pay
  the heal cost. It does not estimate enemy damage per round. The cards do not
  carry that number.
- Priority 4.2, in part. Among similar stagger scores, a danger move adds a
  small amount and a call mark adds a little less. The book has danger, call,
  soft, and shift. It has no support mark, so there is no support term.
- Priority 6, the redundant allyCritical check. The inner condition was always
  true. It is gone.
- Priority 4.4, update the design doc where policy and code were going to
  differ. The player asked for that update. README.md and the design doc now
  match the playtest script: the wheel is the player's when the Finish Blow is
  not found, a danger gauge raises the recover line to 65%, the book gauge
  latches the break, and a missed bonus keeps the poured stagger.

What was tried from the fix list and then rejected by fights
- Priority 2, raise the recover line from 50% to 65% while any danger card is
  up, and allow that heal when the bonus has not just ended. This was put into
  the local script. The fights rejected it. On The Hunger, potions and Cures
  went out for allies at 48% to 62%. On a Goblin pack, gauge 50, Goblin Punch
  was enough to potion people at 40% and 46% before the chip. Survival on the
  boss was better. The stagger loop got slow, because anyone who was not the
  single weakness payer stopped to top the party off. The player cannot discard
  potions. A full bag is the normal case. The testing branch still has the 65%
  branch, because that is the script the playtests ran. v0.1.3 did not remove
  it. Do not delete it on this branch to match an older note. A later change
  needs a new set of fights.
- Priority 5, prefer the live gauge when it disagrees with the card. The live
  break ratio stays full after a hit, so there is no live remainder to prefer.
  The stand-in that was coded, Fight.gaugeScale, keeps poured stagger when a
  latch is released and grows a working gauge to about poured/0.72. The math
  runs. The fights showed it ratcheting: one boss went 450, then 639, then 889,
  and a Goblin went from 50 to 104, which then split the rest of the pack. The
  cause is that a full forecast is treated as a finished break. Hits during
  that window are not poured, and the burst starts while the phase is still
  Normal. The testing branch still latches at the book gauge and still grows
  by about poured/0.72 when the bonus does not arrive. v0.1.3 keeps that path.
  The learned size stays for the rest of the battle and a new battle clears it.
  Do not replace that path on this branch without a new fight log.

What the fix list cannot use, because the game does not expose it
- Priority 1A, learn an element by comparing the gauge drop with the preview.
  GetBreakPointRatio stays full. A 3x or 0.5x drop is not observable. Do not
  add a learner that records a match from a gauge that does not move.
- Priority 1B, read an element field off the skill row. buildSkillIndex already
  reads the row. The row has cost, power, stagger, target, and effect. It has
  no element column. Element stays in Scripts/known.lua. An unnamed Vision
  spell is still cast, ranked by its own stagger, with factor 1 until the
  catalog names the element. Libra still runs when the name is missing or the
  card says the weakness shifts.
- Priority 4.3, Timeline heals and "skip the heal because the stagger is
  guaranteed." GetTurnVM throws. Party order is the stand-in. The design doc
  used to tell the planner to read the Timeline. That instruction is removed.
  Do not call GetTurnVM.
- Priority 5, a difficulty field that scales the Normal gauge in mobs.lua. None
  was found. Do not invent one from a single fight's enemies. One fight is
  evidence for a rule. It is not a new card.
- Priority 6, a headless simulator and a startup game-version check. Not built.
  UE4SS 3.0.1 is the version the README already names. The 200-local cap is
  real. luac5.4 -p is the check. A hand-rolled local counter has already
  reported a false overflow. Do not split turn() into chunk-level functions to
  satisfy a bad count. Declare Fight and unitKit before any function that
  closes over them. Lua 5.4 has no continue and no goto. and/or bind tighter
  than comparison. Parenthesize mixed conditions.

1. Stagger planning ignores the live gauge. [read, data]
   Where: main.lua:2947 (gaugeOfEnemy), main.lua:3041-3047, main.lua:4469,
   main.lua:4818, main.lua:5985 (ledgerOnly).
   What: gaugeOfEnemy works out what is left as the book gauge minus Fight.poured,

   What: after one cast that missed, landRate returns 0. Expected damage and

   Reproduced: noteCast(book, 1, 100, false), then landRate(book, 1, 100, 100)

   Where: main.lua:3406-3428 (healNow), main.lua:3438, main.lua:1495 (legalize).

   because cost is floored at 1. spellRank gave Chakra 100, Cure 33.3, Curaga 30.
   Effect: legalize sends a self row to the caster, but the hurt ally is still
   marked as healed. They get no heal, and the claim stops others healing them.

   Where: main.lua:588, items.lua:70-73, items.lua:236.
   What: main.lua reads Rare and IsRare. CONSUMABLES_ITEM_DATA has neither field,

   IsAbleRecoverMagicPoint answers yes.
   Docs: README line 124 says rare items are saved.

   Where: main.lua:558-567, main.lua:2806, main.lua:4462. Commit c535da7 removed

LIMIT GAUGES, FROM THE 2026-11-05 LOGS

The played report never commanded a Limit of either gauge cost. The point bar
the report prints (the unit parameter) peaked under one gauge: Lasswell 97,
Fina 97, Nichol 79, Rain 50. One gauge is 100 points. GetLimitBurstPointOneGauge
returned 100. Nichol's max is 100, so his bar holds one gauge. Rain, Lasswell,
and Fina max at 200, so theirs hold two. A two-gauge row needs 200 points.
Nobody reached that, so this log cannot show a level-2 cast. It also cannot
show a level-1 cast.

The ready check was still wrong for the next fight that does fill. v0.2.24
(cf1d87a) and this build shared it. GetUnitLimitBurstPointGaugeNum returned 0
on every logged read. The first 0 set a process flag, and after that the
gauge count replaced the points. A library point read of 0 is a number, so
the unit parameter was never consulted. A later full bar would stay unread
if that count stayed 0. The flag is gone. Filled gauges are the highest point
read divided by the one-gauge size. The count is used only when the points
are missing.

When a Limit is spent, the same comparison as before picks it: more kills,
then damage, then stagger. Two ready Limits break the remaining tie by gauge
cost, so the row that spends more of the bar wins. On a break, a ready Limit
is the spend unless another action kills more. That is the old cash bonus
without a score weight. The smaller damage Limit still waits while a larger
one on that ally can land and a foe is unbroken. It is not a boss flag.
A full bar, or a break of the largest gauge, spends the larger row.

This note was written before the next play. That play is in CURRENT LIST.
The tests check the gauge math and the comparison. They do not fight the game.
